# Как править этот рис

Рис личный, но правкам рад. Пара договорённостей, чтобы ничего не разъехалось.

## Где что менять

| Хочешь | Правь |
|---|---|
| цвета, прозрачность, анимации, сессию, раскладку | `vxwm/rice/rice.toml` (и шаблоны в `vxwm/rice/templates/`) |
| новую тему | палитру в `vxwm/rice/palettes/` — остальное сгенерируется |
| хоткеи, правила окон, теги | `vxwm-src/config.def.h` |
| возможности самого WM | `vxwm-src/modules.def.h` |
| бар | `vxbar/src/` |
| приложение настроек | `vxbar-settings/` |

Сгенерированные конфиги (`~/.config/rofi/config.rasi`, `kitty.conf`, `dunstrc`,
`picom.conf`) править бесполезно: следующий `vxwm-rice-apply` их перепишет.
Меняй шаблон, из которого они собираются.

## Проверить перед PR

```bash
./install.sh --fresh --dry-run                      # установщик не сломан
./install.sh --existing --dry-run -y                # и второй режим тоже
HOME=$(mktemp -d) python3 vxwm/rice/mktheme.py      # все палитры собираются
HOME=$(mktemp -d) python3 vxwm/rice/apply.py --dry-run
make -C vxwm-src                                    # WM собирается
cargo build --release --manifest-path vxbar/Cargo.toml
cd vxbar-settings && go test ./...
```

То же самое гоняет CI на каждый push.

## Комментарии

В этом репозитории комментарии объясняют **почему**, а не что: почему бинарь
ставится через временный файл, почему затухание пружины ниже критического,
почему картинка не обновляется без рестарта dunst. Код и так видно — не видно
причин, по которым он такой. Держись этого стиля, он здесь везде.

Язык комментариев — русский, как и во всём остальном репозитории.

## vxwm-src

Это вкопированный форк [vxwm](https://codeberg.org/wh1tepearl/vxwm), а не
подмодуль: часть модулей (`externalbar`, `tagslide`) существует только здесь, и
без них рис не работает. Правки самого оконного менеджера — сюда; то, что имеет
смысл и без риса, стоит отнести и в апстрим.
